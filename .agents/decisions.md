# Architecture Decisions (ADRs)

## Record Format
### [YYYY-MM-DD] ADR-Title
- **Context**: Why was this decision necessary?
- **Decision**: What was chosen?
- **Consequences**: What trade-offs or constraints follow?

### [2026-08-17] agent-ctx dump regenerates the symbol map live, never from cache
- **Context**: `dump` read the cached `.agents/repo_map.md` from disk. That file only updates when someone remembers to run `agent-ctx map`, so it silently drifted out of sync with the repo (missing an entire directory added in the very commit that last refreshed it) with no timestamp or signal telling an agent the data was stale. The `agent-context` skill tells agents to trust `dump`'s output over grepping, so stale data there is actively worse than no tool.
- **Decision**: `cmd_dump` now calls `generate_repo_map(root)` directly instead of reading `repo_map.md` from disk. The on-disk `repo_map.md` file (written by `init`/`map`) is kept only for humans/other tools browsing the repo directly.
- **Consequences**: `dump` is now immune to map staleness by construction, at the cost of a full repo walk on every `dump` call instead of a file read. Acceptable since `generate_repo_map` is a plain `os.walk` with no external calls. `.agents/activity.jsonl` was also un-ignored (previously caught by the repo's blanket `*.jsonl` gitignore rule) so the activity log — the one part of `.agents/` that was actually being populated — is now shared via git instead of staying local-only.

### [2026-08-17] agent-kb relocated into this repo, trimmed to what actually works
- **Context**: `agent-kb` lived in a separate, unpublished repo (`~/projects/agent-error-kb`) and was referenced by `claude/skills/agent-error-kb` only by absolute path, so it wasn't portable across machines and wasn't part of this repo's install story. On inspection it also barely got used (15 DB rows, 12 of them seed data, 2 self-test artifacts, exactly 1 real record in ~13 days) and its MCP server mode was flat-out broken: `mcp_server.py` called `mcp.types.ListToolsRequestSchema`, which doesn't exist in the installed `mcp==2.0.0` SDK — confirmed by importing it directly and by running the project's own `tests/test_mcp.py`, which fails at import. `db.py` also had a `get_metrics()` method, never called from anywhere, that returned a hardcoded `"active_agent_queries": 142`, and an `errors_fts` FTS5 index that was written to on every insert but never queried (`search_solutions` does a full table scan + Python-side token/n-gram scoring instead).
- **Decision**: Moved the project into `bin/agent-kb/` in this repo (own `pyproject.toml`/`uv.lock`/`.venv`, not stdlib-only like `agent-ctx`). Dropped `mcp_server.py`, the `mcp` CLI command, the `mcp` dependency, the `errors_fts` table and its write path, and the dead `get_metrics`/`get_analytics` methods. Fixed `pyproject.toml`, which was missing a `[build-system]` table — `uv sync` was silently skipping entry-point installation, so the `agent-kb` console script only ever existed because of a hand-written wrapper script with a hardcoded `/home/devhax/...` path (also fixed, now `Path.home()`). Wired venv creation + symlinking into `setup.sh`, alongside `agent-ctx`.
- **Consequences**: `agent-kb` now installs correctly via `uv sync` (or a `pip install -e` fallback) and its console script is portable across machines. Only `lookup`/`record`/`patterns` remain — no MCP integration. If MCP support is wanted later, it needs to be rewritten against the current `mcp` SDK's actual decorator API (`@server.list_tools()`/`@server.call_tool()`), not restored from the old code.

### [2026-08-17] The repo map ranks and orients; it does not enumerate
- **Context**: The map was a flat, alphabetically-sorted file listing with bare symbol names, capped at `max_files=150`. Three problems. (1) The cap was silent: the header printed the *full* file count while the body emitted only the first 150 entries, so on a 201-file repo an agent read "201 files" and had seen 150 — and because the sort was alphabetical, the dropped half was always the back of the alphabet (`src/`, `tests/`, `utils/` cut while `.github/` survived). (2) The hand-rolled `.gitignore` parser was wrong in both directions — confirmed: negations (`!keep/x.jsonl`) were discarded so `.agents/activity.jsonl` was invisible in this repo's own map despite being deliberately un-ignored; path-scoped patterns (`logs/debug.txt`) and trailing globs (`tmp*`) leaked ignored files in. (3) More fundamentally, enumeration is what `Glob`/`Grep` already do better — the map spent all its bytes and all its bug surface re-deriving a directory listing while answering none of the questions an agent actually has at cold start.
- **Decision**: Rebuilt the map around ranking instead of listing. File visibility now comes from `git ls-files --cached --others --exclude-standard` (git owns gitignore semantics; the `os.walk` + `DEFAULT_IGNORES` path survives only as a non-git fallback). Files are ranked by import in-degree (4×) + 90-day commit churn + entry-point detection, then rendered in tiers: core (entry point or in-degree ≥ 2) gets full symbols, supporting gets a compact line, the rest collapse per directory. Symbols now carry real signatures via `ast.unparse(node.args)` plus return annotations and `:line` numbers; module docstrings are surfaced; private methods are filtered. The file-count cap is replaced by a character budget (`--budget`, default 12000; `dump` uses 9000) that always announces what it collapsed. `dump` gained a working-state block (branch, uncommitted files, last 5 commits) and per-section budgets for `memory.md`/`decisions.md`, the latter keeping the newest ADRs.
- **Consequences**: The map now answers "what matters here", "what imports what", and "where do I start" — the three things `Grep` cannot answer in one call — and `dump` is a genuine one-shot orientation (11.6k chars, ~0.12s on this repo). The import graph resolves Python and relative JS/TS only; Go/Rust/C get symbols and churn ranking but no edges, because a guessy resolver would inject false edges and corrupt the ranking that everything else now depends on. Ranking requires parsing every file before knowing which ones will be collapsed, so the budget bounds output size, not wall-clock. `get_git_branch` now returns `None` outside git and `detached@<sha>` on detached HEAD instead of fabricating `"main"`, so `activity.jsonl` records stop carrying invented branch names.

### [2026-08-17] Import-graph ranking must resolve path aliases and framework conventions
- **Context**: The ranked map was validated only against agents-config (38 files, mostly Python), which hid three defects that `~/projects/fusuycorp/titirek` (162 files, Next.js/TS/PocketBase, actively developed) exposed on first run. (1) The JS/TS resolver handled only relative specifiers; measured on titirek, `@/…` alias imports outnumber relative ones **401 to 26**, so the graph resolved ~6% of internal edges and in-degree ranking was effectively inert — the map was ordered by churn alone. (2) `index.ts` was in `ENTRY_NAMES`, so barrel re-export hubs were labelled entry points while the real ones — 22 App Router `page.tsx`/`layout.tsx`/`route.ts` files — went undetected. (3) The symbol regexes matched neither `export default function` (the Next.js page form) nor `export const` (the common React component form), so route and component files parsed as having no symbols and were collapsed into the "Other files" bucket.
- **Decision**: Resolve `compilerOptions.paths` from `tsconfig.json`/`jsconfig.json` (JSONC-tolerant parse) and use it for bare specifiers; drop `index.*` from `ENTRY_NAMES` and detect file-system routes (`page`/`layout`/`route` under `app/`|`pages/`, plus `middleware`) instead; match `export default` and `export const`. Files with no parsed symbols but in-degree ≥ 2 are still shown, since the importer list is itself the signal. Importer labels are de-duplicated and generic stems (`page`, `index`, `layout`) are qualified with their directory, because a route-based project has a dozen files named `page`. `dump` now spends one total budget in priority order memory → decisions → map, with the collapsed-dirs tail reserved for rather than emitted unbudgeted.
- **Consequences**: On titirek the graph went from ~26 to **464 resolved edges** (75 of 162 files with importers), and the top of the map became the genuine shared core — `components/ui/button.tsx` (39 importers), `lib/utils.ts` (29), `types/pocketbase-types.ts` (27), `lib/pocketbase/session.ts` (26) — instead of an alphabetical accident. `dump` is 23.3k chars / ~0.14s there and 18.1k on agents-config, both inside the 24k budget. The standing rule this establishes: **validate map changes against titirek, not agents-config** — a small single-language repo cannot exercise ranking. Any language added to the graph must also handle its module-resolution config, or its edges are decorative.

### [2026-08-17] Budget presets, and priority-based trimming instead of positional clipping
- **Context**: Measured the budget/return curve on titirek and a 12k-file synthetic repo. Raising the budget costs **tokens, not time** — map generation is flat (~1.2s) at every budget — and it saturates: titirek's map stops growing at 27.6k chars, after which extra budget buys literally nothing. But saturation is O(repo size): uncapped, the 12k-file repo renders **4.3MB (~1.09M tokens)**, several times a full context window. So a single fixed "immense" number is meaningless — it is free on one repo and catastrophic on another. Separately, both prose trims were ordered backwards. `decisions.md` was tail-clipped (keep newest), but ADRs are not news — titirek's ADR-001 (app shell) and ADR-003 (zero client-side PocketBase / IDOR defense) are foundational, and it was on track to exceed its cap within a day at ~1.6 ADRs/day over its 5-day life. `memory.md` was head-clipped, which keeps "Active Epics" (the disposable changelog) and drops "Domain Vocabulary & Gotchas" (durable). A greedy priority fill was also wrong: it dropped Core Invariants whenever that section was the largest and backfilled with smaller, less important ones.
- **Decision**: `--budget <chars|default|large|immense>` (plus `AGENT_CTX_BUDGET`) on both `map` and `dump`; `large`=60k, `immense`=200k, deliberately no "unlimited". `dump` splits its total as one third memory, one third decisions, remainder to the map, so a bigger preset helps every section. Trimming is now structural: `decisions.md` keeps **every ADR title** and expands bodies newest-first (titles cost ~60 chars, so the full decision list stays visible indefinitely); `memory.md` trims by section priority (invariants → gotchas → status) and **truncates** an oversized top-priority section rather than dropping it. Heading level is detected, not assumed — titirek writes `## ADR-001:` while the template writes `### [date]`.
- **Consequences**: Nothing is ever silently invisible: an agent always sees the complete list of decisions and every section heading. On titirek `default` is 23.0k chars and `large`/`immense` are byte-identical at 46.0k (saturated), which is the empirical case for staying on `default` unless exploring an unfamiliar large repo. `clip_lines` is deleted. The dominant remaining growth risk is that `decisions.md` is append-only with no pruning story — budgets bound what is *shown*, not what accumulates.
