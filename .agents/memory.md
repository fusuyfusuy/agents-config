## Core Invariants & Architecture Rules

- **Stdlib only.** `tui-agent-settings/skills/agent-context/agent-ctx` never takes an external dependency; installed by symlink, not package manager. (`tui-agent-settings/skills/agent-error-kb/agent-kb` opposite — own venv/`uv.lock`.)
- **Git is authority on file visibility.** File listing via `git ls-files --cached --others --exclude-standard`. Never hand-parse `.gitignore` — old parser got negations, path-scoped patterns, trailing globs all wrong. `os.walk` + `DEFAULT_IGNORES` path: fallback for non-git dirs only.
- **No silent caps.** Any truncation in map or `dump` must state it happened + how much withheld. Quiet cap makes agent believe it saw whole repo. Invariant behind character-budget design and "Detailed N of M" footer.
- **Never fabricate git metadata.** `get_git_branch` returns `None` outside git, `detached@<sha>` on detached HEAD. Previously returned `"main"` unconditionally on failure — wrote false data into permanent activity log.
- **Ranking beats enumeration.** Map's job: orientation (what matters, what imports what, where to start), not listing — `Glob`/`Grep` already enumerate better. Anything added to map must earn its bytes against that standard.
- **`tui-agent-settings/skills/ponytail-debt/`** harvests `ponytail:` deferral comments into a ledger — adapted from [DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail)'s skill of the same name, not copied verbatim. Diverges 4 ways, each found by dogfooding it on this repo + titirek: (1) upstream's `grep -rnE '(#|//) ?ponytail:'` misses markers inside docstrings/block comments (real miss: `agent-ctx`'s own `build_import_graph` marker) — added a loose second pass; (2) that loose pass first tried allowlisting code extensions and *still* missed `agent-ctx` because it's extensionless — switched to blocklisting prose/data formats (`.md`/`.txt`/`.json`/`.jsonl`/...) instead, which catches shebang scripts for free; (3) added duplicate-marker detection (titirek had the same marker copy-pasted into 3 action files); (4) tightened "no-trigger" to require a named condition/dependency/threshold/owner, not just a stated fix direction — upstream's looser definition would've missed 2 real rot-risk markers in titirek that named a fix but not a trigger. Also: use `command grep` in this skill, not bare `grep` — this sandbox shell-wraps `grep` through `ugrep` with injected flags that combine multiple `--exclude` globs differently and produced a false positive on `activity.jsonl`.
- **Writing style: caveman, docs-only.** `memory.md`/`decisions.md`/`log --summary` follow the [JuliusBrussee/caveman](https://github.com/JuliusBrussee/caveman) skill's compression rules (drop articles/filler/hedging, keep code/paths/numbers/errors exact, never drop not/never/no/only) — full rule list in `agent-context` SKILL.md §3. Adopted the rule list only, not their mechanism: their `caveman-compress` skill shells out to Claude to rewrite files, which would break the stdlib-only/zero-daemon invariant above. No new code, no self-check needed — this is phrasing discipline, not logic.

## Domain Vocabulary & Gotchas

- **in-degree**: how many local modules import a file — map's primary importance signal, shown as `← cli, db, ...`. **churn**: commits touching file in last 90 days. **tiers**: `core` (entry point or in-degree ≥ 2, full symbols) → `supporting` (compact one-liner) → collapsed by directory.
- Import graph resolves **Python (`ast`) and JS/TS (relative + `tsconfig`/`jsconfig` path aliases)**. Go/Rust/C deliberately no edges — guessy resolver injects false edges, wrong ranking worse than absent ranking. See `ponytail:` note in `build_import_graph`.
- **Path aliases not optional.** In titirek, `@/…` imports outnumber relative ones **401 to 26** — relative-only resolution captured ~6% of edges, left ranking churn-driven. New language added to graph must handle its alias/module-resolution config, or graph is decorative.
- Framework conventions matter for entry points: `index.ts` usually **barrel re-export hub, not entry point** (was mislabelled); Next.js `app/**/page.tsx`, `layout.tsx`, `route.ts`, `middleware.ts` **are** entry points. `export default function` + `export const` must both be captured as symbols — miss them, blanks out most React components.
- `dump` spends total character budget (`DUMP_TOTAL_BUDGET`) in priority order: **memory → decisions → map**. Hand-written stores win — can't be recovered from code; map is derivable, re-queryable with Grep, absorbs remainder down to floor. Every section emitting text must be counted, including collapsed-dirs tail (`COLLAPSE_RESERVE`) — unbudgeted tail silently blows total.
- **Recent Activity tail itself capped (`DUMP_ACTIVITY_BUDGET`, 1200 chars), not just counted.** On titirek, 5 unbounded `log` entries (long summaries + file lists) cost 3.5k chars — near as much as whole map got, left only 5/232 files detailed. Per-entry summaries elide past `ACTIVITY_SUMMARY_LIMIT`, file lists past `ACTIVITY_FILES_SHOWN`; entries dropped oldest-first if still don't fit, always with `_N of M entries shown_` notice. Self-check: `_test_activity_tail`.
- **`agent-ctx log` warns (doesn't block) when `--summary` exceeds `ACTIVITY_SUMMARY_LIMIT` (160 chars).** Fixes problem at source, not just read-time: verbose logger used to get silently elided by `dump`, no feedback, summaries drifted into implementation-detail prose. Full record still written to `activity.jsonl` either way — `agent-ctx history` shows it in full — warning only nudges toward high-level "what and why". Self-check: `_test_log_summary_length`.
- Extensionless executables (e.g. `agent-ctx` itself) parsed by **shebang sniffing** — without it, tool couldn't map itself.
- `.agents/activity.jsonl` visible only via `!.agents/activity.jsonl` negation in `.gitignore` fighting blanket `*.jsonl` rule — exactly the case old ignore parser silently got wrong.
- `dump` costs full repo walk + AST parse every call — ~0.12s, ~11.6k chars on this repo. Both scale with repo size; character budget is safety valve, wall-clock not bounded.
- `agent-ctx --test` is whole test suite (no framework), mutation-checked: breaking budget notice, import graph, or branch detection each make it fail.
- **Antigravity's quota API has multiple independent reset buckets keyed by model, not one global quota.** `GetUserStatus` → `cascadeModelConfigData.clientModelConfigs[].quotaInfo` returns `remainingFraction`/`resetTime` per model; different model families sit on different buckets — e.g. Claude/GPT-OSS share 5h rolling sprint bucket, all Gemini 3.x variants (Pro/Flash × effort tier) share separate multi-day/weekly bucket. To avoid misleading/conflicting displays, `tui-agent-settings/antigravity-cli/status.py` and `tui-agent-settings/tmux/plugins/tmux-agent-quotas/scripts/fetch_quotas.py` use `select_gating_quota()`: matches active session model's quota if present, else falls back to most constrained model (`min(remaining_percentage)`, broken by soonest `reset_time`). In tmux, Claude Code instead always surfaces the 5h rolling window, falling back to 7d only when 5h data is absent — 5h is what a user actively watches session-to-session; showing whichever window is numerically tighter made the display flip to the 7d bucket unpredictably. Self-check: `tui-agent-settings/tmux/plugins/tmux-agent-quotas/scripts/test_quota_selection.py`.
- **pi persists per-message cost in session files.** `~/.pi/agent/sessions/**/<ts>_<uuid>.jsonl` stores `usage.cost.total` on assistant/toolResult messages (`message.usage.cost.total`), directly on `compaction`/`branch_summary` entries too — pi's own `getUsageCostBreakdown()` sums exactly those. So pi spend reconstructable offline, no pricing catalog or provider API needed. `tmux-agent-quotas` now shows today's pi spend (`PI $X.XX`, local-midnight reset) via `compute_pi_today_spend()` in `fetch_quotas.py` — mtime-gated to files touched today to stay cheap; self-check `scripts/test_pi_spend.py`.
- **pi extensions for this machine live in both repo (`tui-agent-settings/pi/extensions/`) and `~/.pi/agent/extensions/`** (identical copies, synced manually). `gated-tools.ts` predates; `compact-tools.ts` (added 2026-08-19) re-registers built-in tools with compact TUI rendering only — execution delegates to `createXTool(cwd)` originals. Renderers must not call `keyHint()` — crashes outside live keybinding context (caught by smoke test); static hints safe.
- **OpenCode Go `/zen/go/v1/usage` `resetsAt` = NEXT reset (future), not period start.** Weekly covers since `resetsAt−7d`, monthly since `resetsAt−1 calendar month`, 5h rolling since `now−5h`. Subtract, don't truncate at `resetsAt` — treating it as a lower bound zeroes out the whole current period. `ocgo.py` (`subtract_period`) handles it; self-check `test_ocgo.py::test_subtract_period_monthly`.
- **OpenCode Go paid bucket == `providerID=="opencode-go"` only.** opencode.db also holds free providers (`opencode`/`deepseek-v4-flash-free`) that don't count against the plan; filter by model prefix `opencode-go/` (result of `collect_agent_usage`'s `provider/model` join). `ocgo` CLI (`~/.local/bin/ocgo`, symlink via `setup.sh install_shared`) shows quota windows + who-ate-it; reuses `collect_agent_usage.parse_opencode`.
- **Root/worker subagent delegation rule removed 2026-08-20 — proved unenforceable.** Old rule said "delegated worker must never spawn further subagents"; prose-only, nothing blocked a worker calling `subagent` again, workers recursed anyway. Replaced with: long/multi-step/unattended work routes through `pi-goal-list-loop-audit` (`/goal`, `/list`) instead of ad-hoc subagent chains — its detached, extension-less auditor process structurally can't be called recursively by a worker and independently re-verifies completion against a contract (`regression_shield`: raw command output required per contract item). Ordinary short/bounded delegation still uses plain `subagent` calls; no more root/worker split rule. Requires `@juicesharp/rpiv-ask-user-question` for real UX (else prose fallback); AGPL-3.0; hard-conflicts with any other `agent_end`-driving plugin (`pi-codex-goal`, `ralphi`, `pi-loop-mode`, etc.) — none installed here.
- **`pi-lens` installed (v4.0.1, MIT) — real-time LSP/lint/type-check/structural feedback on every write/edit**, not a one-shot linter run. Covers: LSP diagnostics + navigation, impact-cascade diagnostics (related files affected by a change also get checked), language linters/type-checkers/scanners, safe autofix where configured, ast-grep + tree-sitter structural rules (security/correctness smells), `symbol_search` ranked identifier search feeding a discovery funnel (`symbol_search` → `module_report` → `read_symbol`), diagnostic triage dispositions (false-positive/suppress/defer/flagged-to-fix, honored everywhere), `/lens-map` HTML dependency map, read-guard + edit-autopatch to reduce bad edits, `/lens-health` degradation ledger (LSP breakers, formatter skips, timeouts), experimental MCP server so non-pi clients (Claude Code) can reuse the same diagnostics tools. npm v12: install-script approval may be needed for `@ast-grep/cli` postinstall (`npm approve-scripts` or trust declared `allowScripts`).
